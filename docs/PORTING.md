# Porting Maxima's Lisp to MoonBit — conventions

This repository ports Maxima (Common Lisp, `.repos/maxima/src/*.lisp`) to
MoonBit. The port is a **faithful, function-by-function translation** that
keeps Maxima's internal representation (Lisp s-expressions such as
`((mplus simp) 1 $x)`), so behavior can be compared directly with the
original and Maxima's own test suite (`tests/rtest*.mac`) can be reused.

Read this whole file before translating anything.

## Layout

- `lisp/` — the Common Lisp runtime: `Value`, symbols, conses, numbers,
  strings, hash tables, arrays, streams, `format`, a literal reader. Its
  public API is listed in `lisp/pkg.generated.mbti`. Everything is imported
  into `core` by `core/gen_using.mbt`, so call runtime functions unqualified.
- `core/` — ONE package holding all translated Maxima code.
  - `gen_*.mbt` — GENERATED by `tools/gen.py`. **Never edit.**
    - `gen_decls.mbt`: a `declare fn` for every Lisp function (and every
      function-like macro) in Maxima. This is the shared contract: you
      implement the declarations for your file; you call any other
      function through its declaration even if nobody has ported it yet.
    - `gen_symbols.mbt`: `q_*` symbol constants.
    - `gen_registry.mbt`: installs every function in its symbol's function
      cell (so `funcall`/`apply`/Maxima calls work), `defmspec`s on the
      `mfexpr*` property, and `def-simplifier` properties.
    - `gen_vars.mbt`: literal initial values of special variables.
  - `glue.mbt` — hand-written helpers used everywhere (see below).
  - `<lispfile>.mbt` — your translation of `src/<lispfile>.lisp`
    (`-` becomes `_`; split big files as `<lispfile>_1.mbt`, `_2`, ... ).
- `docs/index/functions.tsv` — Lisp name, kind, source location, MoonBit
  signature, for every declared function. `tools/sig.sh <lisp-name>...`
  prints entries.
- `docs/index/specials.txt` — every special (dynamically scoped) variable.
- `docs/index/macros.tsv` — every `defmacro`.
- `docs/index/complex_var_inits.tsv` — `defvar`s whose initial value is not
  a literal; the porter of that file must initialize them (see Init).

## Names

A Lisp name maps to a MoonBit identifier by `tools/gen.py:mangle`:

| Lisp | MoonBit function | symbol constant |
|------|------------------|-----------------|
| `simplifya` | `simplifya` | `q_simplifya` |
| `$ratsimp` | `d_ratsimp` | `q_d_ratsimp` |
| `%sin` | `p_sin` | `q_p_sin` |
| `*expandp*` | `ear_expandp` | `q_ear_expandp` |
| `add*` | `add_star` | `q_add_star` |
| `simp-%sin` | `simp_p_sin` | `q_simp_p_sin` |
| `:test` | — | `q_kw_test` |
| `bigfloat::foo` (in-package bigfloat) | `bf_foo` | `q_bf_foo` |

`-`→`_`, `*`→`_star`, `%`→`_pct`, `$`→`_dol`, `+`→`_plus`, `/`→`_sl`,
`=`→`_eq`, `<`→`_lt`, `>`→`_gt`, `?`→`_q`, `!`→`_bang`, `&`→`_amp`,
`.`→`_dot`, `^`→`_hat`. A name that would collide with a MoonBit keyword, a
runtime function, or a glue function gets a trailing `_` (e.g. Maxima's
`memq` is declared `memq_`; use the runtime `memq`). A few names were
disambiguated (`d-box` → `d__box`, `gamma_incomplete` →
`gamma_u_incomplete`). **Never guess**: look up names with
`tools/sig.sh name` and `tools/q.sh name` (prints the `q_` constant and
function name).

Symbol names in the port are exactly what the Maxima user sees: user `foo`
is the symbol named `"$foo"`, user `Foo` is `"$Foo"`, Lisp `mplus` is
`"mplus"`. CL Maxima instead stores upcased names and inverts case when
printing. Consequently:

- `print-invert-case`, `maybe-invert-string-case` and friends are the
  identity in the port.
- Case-agnostic string surgery on symbol names (`(subseq (symbol-name x) 1)`,
  `(concatenate 'string "%" ...)`) works unchanged on port names.
- Code that explicitly upcases/downcases names to build CL symbol names must
  be translated to produce the *port* name. The CL-name ↔ port-name
  conversion is `invert_case` (runtime), which swaps the case of
  uniform-case strings: CL `"$FOO"` ↔ port `"$foo"`.

## Values

```moonbit
enum Value { Nil; Sym(Symbol); Cons(Cons); Fix(Int64); Big(BigInt);
  Ratio(BigInt, BigInt); Flo(Double); Cplx(Value, Value); Str(String);
  Char(Char); Vec(LArray); Hash(LHash); Func(LFunc); Struct(LStruct);
  Stream(LStream); Box(Ref[Any]) }
```

- `nil`/false/empty list is `Nil`; `t` is `t` (also `q_t`). Lisp truth:
  `x.truthy()`, `x is Nil`, `null(x)`. Bool→Value: `lbool(b)`.
- Every translated function takes and returns `Value` (see signatures);
  predicates therefore return `t`/`Nil` — test them with `.truthy()`.
- Lisp integers are `Fix(Int64)` or `Big`; build with `int(n)`,
  `Fix(5L)`, `from_big(b)`. Maxima rationals are `((rat simp) n d)` lists,
  NOT `Ratio` (a CL ratio is a different object; it appears only where the
  Lisp code really does CL rational arithmetic).
- Floats are `Flo(Double)`. Bigfloats are `((bigfloat simp prec) mant exp)`.
- Strings: `Str(s)`; characters: `Char(c)`.

## Lists

`car cdr caar cadr cddr caddr cadddr ... cons list1 list2 list3 list4
list([..]) list_star([..]) append nconc reverse nreverse length nth nthcdr
last member memq member_equal assoc assq assoc_equal rassoc getf remove
delete remove_if mapcar mapc mapcan maplist every some find_if position
subst sublis copy_list copy_tree sort_list ...` — see the runtime mbti.
`car`/`cdr` of non-lists return `Nil` (no error). Iterate with
`for x in l.iter() { ... }`. `Collector` builds lists front-to-back.
`rplaca`/`rplacd`/`setf_car`/`setf_cdr` mutate. `physical_equal_value`
tests cons identity.

Pattern matching on `Value` is often the clearest translation:

```moonbit
match e {
  Cons({ car: Cons({ car: Sym(_) as op, .. }), cdr: args }) => ...
  _ => ...
}
```

Glue helpers: `op_of(x)` = `(caar x)` for non-atoms (else Nil);
`is_op(x, q_mplus)` = `(and (consp x) (eq (caar x) 'mplus))`;
`mk(q_mplus, [a, b])` = `` `((mplus) ,a ,b) `` (fresh header);
`mk_simp(q_rat, [n, d])` = `((rat simp) n d)`.

## Equality

`eq` (identity; fixnums/chars by value), `eql`, `equal` (structural),
`equalp`. Never use MoonBit `==` on `Value`. Maxima's `alike1`/`like` are
translated functions in `core`.

## Arithmetic (CL generic)

`num_add num_sub num_mul num_div num_neg num_abs num_lt num_gt num_le num_ge
num_eq num_compare zerop plusp minusp oddp evenp num_floor num_ceiling
num_truncate num_round` (these return `(quotient, remainder)` tuples)
`floor1 ceiling1 truncate1 round1 num_mod num_rem num_gcd num_lcm expt
isqrt ash logand logior logxor lognot logbitp integer_length to_double
lfloat rational rationalize numerator denominator signum num_max num_min
lsqrt lexp llog lsin lcos ltan latan lasin lacos lsinh ... realpart
imagpart complex`. Predicates `numberp integerp fixnump floatp rationalp
realp complexp`. `to_int(x)` extracts a small integer as `Int` (raises if
not a fixnum in range). Use MoonBit `Int`/`Int64`/`Double` locally only when
the Lisp code is clearly fixnum/flonum arithmetic.

## Special variables

Every `defvar`/`defmvar`/`defparameter`/`declare-top (special ...)` variable
(see `docs/index/specials.txt`) is a symbol value cell:

- read: `symval(q_d_ratprint)`; truth: `symval(q_x).truthy()`
- assign (`setq`/`setf`): `set(q_x, v)` (returns v)
- dynamic binding (`let` of a special):
  ```moonbit
  with_special(q_d_ratprint, Nil, () => body)          // one
  with_specials([(q_a, x), (q_b, y)], () => body)      // several
  // or, when the body needs early `return`:
  let b = bind(q_x, v)
  defer unbind(b)
  ```
  `defer` runs at the end of the enclosing block; it also runs when an
  error is raised, like `unwind-protect`.
- `boundp(q_x)`, `makunbound(q_x)`.

Lexical (non-special) variables are ordinary MoonBit `let`/`let mut`.
Check `specials.txt` whenever a `let` binds a variable that is not obviously
local — Maxima has many earmuff-free specials (`varlist`, `genvar`, `var`,
`errorsw`, ...). A `(declare (special x))` inside a function also makes
`x` special.

## Functions

- Implement each declared function of your file with **exactly** the
  declared signature (copy it from `core/gen_decls.mbt`, drop `declare`,
  add the body; parameter names may differ). Keep the `///|` block
  separator before every top-level item. Do not mark things `pub`.
- `&optional x` → `x? : Value = Nil` (or the literal default); a
  non-literal default or a supplied-p variable gives `x? : Value` (an
  `Option`, compute the default in the body). Call with `f(a, x=v)`;
  forward an option with `f(a, x?=opt)`.
- `&rest r` → a positional `r : Value` holding the Lisp list. Callers pass
  `list([..])` or `Nil`.
- `&key k` → labeled optional `k? : Value`.
- Maclisp lexprs `(defun f n ...)` take the list of all arguments; `(arg i)`
  is `nth(i - 1, n)`, the count is `length(n)`.
- Functions declared with a tuple return type returned CL multiple values.
  Callers use `let (a, b) = f(..)` or `f(..).0`.
- A Lisp function that returns multiple values but was declared as `Value`
  (the generator missed it): keep the declared function returning the
  primary value and add a helper `<name>_mv` returning the tuple; mention it
  in your report.
- Private helpers that are not in the contract (local `flet`/`labels`
  functions lifted to top level, closures, etc.) must be named
  `<filetag>__<name>` to avoid collisions with other files (e.g.
  `simp__helper`). The same for any new top-level `let`.
- `defmfun $foo` → implement `d_foo` with the Lisp lambda list. The
  registry wraps it with Maxima's arity check; do not repeat it.
- `defmspec $foo (l)` → `d_foo(l)` receives the whole unevaluated form
  `((foo) args...)`.
- `def-simplifier foo (x y)` → implement `simp_p_foo(form, y, z)` doing what
  the macro expands to: `if length(cdr(form)) != 2 { wna_err(...) }`;
  `let x = simpcheck(nth(1, form), z)`; the local `(give-up)` is
  `eqtest(cons(list1(q_p_foo), list([x, y])), form)`. The registry already
  creates `$foo`, `alias`, `reversealias`, `operators`, `noun`, `verb`.
  (`:simpcheck :custom` means args are `nth(i, form)` without `simpcheck`.)
- `defun-prop (f prop) (args) body` → a private function
  `<filetag>__<f>_<prop>` plus, in your init function,
  `putprop(q_f, lfunc("f-prop", args => ...), q_prop)`.
- `defgrad`, `defprop`, `(setf (get ..))`, `putprop`, `mdefprop`, other
  top-level forms → your init function.
- Lambdas: MoonBit closures. When a function must be stored as a Lisp value
  (plist, list, `funcall` argument), wrap it: `lfunc("name", args => ...)`.
- `(funcall f a b)` / `(apply f l)` where f is a symbol or function value:
  `funcall(f, [a, b])` / `apply(f, l)` (every declared function is
  registered, so funcall-by-symbol works). Prefer a direct call when the
  callee is a known constant: `(funcall #'foo x)` → `foo(x)`.
- `(mapcar #'foo l)` → `mapcar(x => foo(x), l)`.

## Macros

- Function-like Lisp macros (plain lambda list, no `&body`) are declared in
  `gen_decls.mbt` like functions (look for `/// macro` comments and
  `macro` rows in functions.tsv). The porter of the *defining* file
  implements them as functions; everyone calls them like functions. Mind
  that macro arguments in Lisp are unevaluated forms — if a macro is used
  as a `setf` place or needs lazy arguments, translate those call sites
  inline instead.
- `mopers.lisp` macros have ergonomic glue versions — use these:
  `take(head, [args])` (head is e.g. `list1(q_p_sin)`), `take_star`,
  `ftake(q_p_sin, [x])`, `ftake_star`, `fapply(op, arglist)`,
  `fapply_star`, `inv(x)`, `inv_star(x)`, `eq0(x)` (`=0`), `eq1(x)`,
  `addn_([a, b, c])` (`(add a b c)`), `addn_star`, `muln_([..])`,
  `muln_star`, `ncmul_([..])`. Two-argument `add`/`mul` are `add2`/`mul2`
  (and `add2_star`/`mul2_star`).
- Other macros (with `&body`, `setf` expanders, `defmacro`s generating
  definitions): expand them by hand at each use. If a body macro from
  another file is used in yours, read its definition in the Lisp source and
  inline the expansion.
- CL macros: `loop`, `do`, `dolist`, `dotimes`, `case`, `typecase`,
  `destructuring-bind`, `multiple-value-bind`, `push`, `pop`, `incf`,
  `when`, `unless`, `cond`, `and`, `or` → MoonBit control flow. `(and a b)`
  returning a value: `if a.truthy() { b } else { Nil }`. `(or a b)`:
  `{ let v = a; if v.truthy() { v } else { b } }`.

## Control flow

- `return-from f v` → `return v`. `(return v)` from a `do`/`dolist` block →
  `break v` / `return` as appropriate. `block`/`return-from` inside
  expressions → a labeled loop or a local closure.
- `tagbody`/`go`, `prog` with tags → `while`/`for` loops with state
  variables; never use exceptions for local `go`.
- `catch`/`throw` → `catch_tag(q_tag, () => body)` and
  `throw_tag(q_tag, v)` (raises `LispError::Throw`).
- `unwind-protect` → `defer`.
- Lisp `error`, `cerror` → `raise SimpleError(msg)` (or
  `Condition(intern("type"), msg, payload)` for typed conditions).
- `handler-case`/`ignore-errors`/`errset`/`errcatch` → MoonBit `catch`, or
  glue `errset(() => body)` (returns `Value?`).
- Maxima errors: `(merror (intl:gettext "fmt ~M") x y)` →
  `merror(Str("fmt ~M"), list([x, y]))` or `merr("fmt ~M", [x, y])`.
  `merror` raises `LispError::Condition(intern("maxima-$error"), msg,
  $error)`; it never returns (its `Value` result type lets you use it in
  expression position). `intl:gettext s` → just `s`.
- Every translated function is `raise` (the generic error type). Inside, call
  raising functions directly; no `try` markers are needed.

## Strings, output, format

- `format` → `format(dest, "ctl", [args])` (dest `Nil` returns `Str`).
  `format_to_string(ctl, [args])` returns a MoonBit `String`.
- `princ`, `prin1`, `print`, `terpri`, `write_string`, `write_char`,
  `fresh_line`, `princ_to_string`, `prin1_to_string`,
  `float_to_string` (SBCL-style float printing).
- Maxima-level formatted output is `mformat`/`mtell` (translated in core).
- `with-output-to-string` → `with_output_to_string(s => ...)`.
- `*standard-output*` is the special `standard_output`
  (`with_special(standard_output, stream, ...)`).

## Literals

- A quoted symbol `'foo` → `q_foo`. If no constant exists (rare), add a
  file-private top-level `let <filetag>__q_foo : Value = sym("foo")`.
- Quoted list structure `'((mplus) 1 $x)` → build it with `mk`, `list`,
  `cons`, or — for big constants — a top-level
  `let <filetag>__lit_n : Value = try! lread("((mplus) 1 $x)")` (the reader
  uses the port's naming convention). Remember quoted structure is shared
  and must not be mutated.
- Backquote → explicit `list`/`cons`/`append` construction.
- `#$expr$` (Maxima syntax at read time) → `maxima_lit("expr")`, which
  parses once and caches (defined with the reader port).

## Structures, excluded subsystems

- `defstruct` → either a MoonBit `struct` (when instances never flow into
  Lisp data) or `make_struct("name", [slots])` with accessors
  `struct_ref(x, i)` / `struct_set(x, i, v)` and predicate
  `struct_typep(x, "name")` (when instances are stored in lists, plists or
  passed as `Value`). Name accessor helpers `<filetag>__<struct>_<slot>`.
- Some subsystems are not ported (the Maxima→Lisp translator `transl*`,
  `plot`, the debugger, the help system, `numerical/slatec` Fortran code):
  their functions are not declared. If your code calls one, replace the
  call with `merr("<name>: not supported in this port", [])` and list it in
  your report.

## Init

Toplevel side effects of your file (properties, `defprop`, `putprop`,
`setf get`, `defmvar` options such as `:properties`/`:setting-predicate`,
non-literal `defvar` initial values listed in
`docs/index/complex_var_inits.tsv`, `def-lbp` etc.) go in

```moonbit
///|
fn init_<file>() -> Unit raise { ... }
```

where `<file>` is the mangled Lisp file name (`simp`, `rat3a`,
`mutils_fn`). Literal `defvar` values are already set by
`gen_vars.mbt` before your init runs. `defvar` only sets an unbound
variable; `defparameter` always sets. Inits run in `maxima.system` build
order.

## Bigfloat package

Files that switch to `(in-package :bigfloat)` (numeric.lisp and parts of
specfn, gamma, ellipt, hypergeometric, nfloat, intpol) define CLOS generic
arithmetic over doubles, complexes and bigfloats; their functions are
declared with a `bf_` prefix. They are ported separately; only the porter
assigned `numeric.lisp` designs that layer.

## Workflow for porting a file

1. Read the Lisp file completely (`.repos/maxima/src/<file>.lisp`) and the
   definitions of macros it uses.
2. Find your declarations: `grep -n '<file>.lisp:' core/gen_decls.mbt`.
3. Write `core/<file>.mbt` (split if > ~2500 lines), translating every
   function, function-like macro and top-level form of the Lisp file. Keep
   comments that explain the math or the algorithm; drop history.
4. `moon check` until there are 0 errors (`tools/errs.sh` gives a compact
   list; `tools/errs.sh | grep <yourfile>` to focus). Warnings are fine.
5. Do not modify files you were not assigned, nor `gen_*`, `glue.mbt`,
   `lisp/` (report needed runtime additions instead, or add a private
   helper in your own file).
6. Report: what you ported, any function you could not port (and why), any
   signature problem (multiple values, wrong arity), runtime/glue additions
   you needed.

Faithfulness matters more than elegance: preserve evaluation order, the
order of `cond` clauses, destructive operations when their effect is
visible, and the exact Lisp truth values returned.
